# 01. 项目总览与架构

## 1.1 项目定位

**Vue.NetCore（VOL）** 是一个**前后端分离**、**支持信创**的快速开发框架，核心目标是：

> 通过代码生成器，把"建表 → 增删改查 → 主从表 → 审批流 → 表单设计"这条链路自动化，让开发者只关注业务逻辑。

## 1.2 业务模块覆盖

仓库内自带 **MES（制造执行系统）** 演示模块，包括：

- **基础数据**：物料、物料分类、客户、供应商、包装方式、仓库、货位
- **生产管理**：BOM 主/明细、生产订单、生产计划、生产报工、报工明细、车间调度
- **质量管理**：质检方案、质检方案明细、质检记录、次品记录
- **设备管理**：设备台账、故障记录、维修记录、维护计划
- **库存管理**：入库、出库、库存、盘点
- **流程审批**：内置图形化审批流（生产报工已接入示例）

> 演示代码可按需删除：`vol.web/src/views/mes` + `vol.api/VOL.MES` + `VOL.WebApi/VOL.Entity` 下的 `mes` 目录。

## 1.5 运行时序：一次"列表查询+新增"的完整调用链

```
[Vue 前端]
   │
   │  1. 用户在 VolTable 输入筛选条件 → 点击"查询"
   ▼
[src/components/basic/VolTable] 
   │  2. 调用 http.post('/api/Sys_User/pageData', params)
   ▼
[src/api/http.js] ─ axios ─→ http://*:9991/api/Sys_User/pageData
   │
   │  3. JwtBearer 认证 (Authorization: Bearer xxx)
   ▼
[VOL.WebApi/Filters/ApiAuthorizeFilter] 
   │  4. 验证 token、解析用户上下文
   ▼
[Controllers / Sys_UserController] (由代码生成器生成)
   │  5. 调用 service.GetPageData(options)
   ▼
[VOL.MES/Services/.../Sys_UserService] (继承 ServiceBase)
   │  6. ServiceBase.GetPageData → repository.FindAsIQueryable
   ▼
[VOL.Core/BaseProvider/RepositoryBase] 
   │  7. 通过 DbContext / SqlSugar 执行查询
   ▼
[DB]  →  返回分页数据
   │
   ▲
   │  8. 数据经过字段权限过滤、汇总、审计状态补充
   ▼
[VOL.WebApi/Controllers] 返回 { status, code, data: { rows, total, summary } }
   │
   ▼
[VolTable] 渲染表格
```

## 1.7 三种使用模式

1. **完整框架模式（推荐）**：直接使用 `vol.api` + `vol.web` + `DB/` 初始化数据库，开箱即用。
2. **SqlSugar 高性能模式**：将后端切换为 `vol.api.sqlsugar`，业务代码几乎零改动。
3. **二开模式**：保留框架核心 `VOL.Core` + 自建业务模块（如新建 `VOL.Order`、`VOL.CRM`），生成器仍可使用。

## 1.8 版本选择

| 后端 | 适用场景 |
|------|----------|
| `vol.api`（EFCore） | 通用项目、追求稳定、官方文档主推 |
| `vol.api.sqlsugar` | 已有 SqlSugar 技术栈、需要更激进的 SQL 控制、MySQL 性能敏感 |

> 两个后端的 `VOL.WebApi/Program.cs` 是差异最大的入口文件，框架其余部分保持高度一致。
