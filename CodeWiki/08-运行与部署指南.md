# 08. 运行与部署指南

## 8.1 本地开发（Windows / macOS / Linux）

### 8.1.1 准备

1. 安装 **.NET 8 SDK**（EFCore 版）或 **.NET 10 SDK**（SqlSugar 版）
2. 安装 **Node.js 20 LTS** + **npm 9+**
3. 准备数据库（任选一种）
4. 安装 **Redis**（可选，`UseRedis=false` 可跳过）
5. 克隆仓库

```bash
git clone https://github.com/cq-panda/Vue.NetCore.git
cd Vue.NetCore
```

### 8.1.2 初始化数据库

按 [07-数据库与脚本](./07-数据库与脚本.md) 选择一种数据库并执行对应脚本。例如 SQL Server：

```sql
CREATE DATABASE vol_v3;
GO
USE vol_v3;
GO
-- 执行 DB/sqlserver/表结构与数据.sql
```

### 8.1.3 启动后端

```bash
# EFCore 版
cd vol.api
dotnet restore
dotnet build
dotnet run --project VOL.WebApi

# SqlSugar 版
cd vol.api.sqlsugar
dotnet restore
dotnet build
dotnet run --project VOL.WebApi
```

> 默认监听 `http://*:9991`，浏览器访问 `http://localhost:9991/` 会重定向到 Swagger。

### 8.1.4 启动前端

```bash
cd vol.web
npm install      # 或 pnpm install / yarn
npm run dev      # vite --host
```

> 默认监听 `http://localhost:9990`，浏览器访问即可看到登录页。

### 8.1.5 登录

- 演示账号：`admin666 / 123456`
- 本地超级管理员：`admin / 123456`

### 8.1.6 常用批处理

```
vol.api/VOL.WebApi/
├── builder_run.bat        # 启动 builder（开发时）
├── dev_run.bat            # 默认 dev 启动
├── dev_run2.bat           # 备用启动脚本
└── tmp.bat                # 临时调试

vol.web/
├── install.bat            # npm install
├── run.bat                # npm run dev
└── build.bat              # npm run build
```

## 8.2 Visual Studio 中调试

1. 打开 `vol.api/VOL.sln`
2. 设置 `VOL.WebApi` 为启动项目
3. F5 启动（默认端口 9991）
4. 另开一个 VSCode 窗口打开 `vol.web`，运行 `npm run dev`（端口 9990）
5. 通过 `http://localhost:9990` 调试

> 注意：使用 `launchSettings.json` 中可修改启动端口和环境。

## 8.3 生产环境部署

### 8.3.1 编译后端

```bash
cd vol.api
dotnet publish VOL.WebApi -c Release -o publish
# 或
dotnet publish VOL.WebApi -c Release -r linux-x64 --self-contained false
```

### 8.3.2 构建前端

```bash
cd vol.web
npm run build
# 产物在 dist/ 目录
```

### 8.3.3 Nginx 反向代理（推荐）

```nginx
server {
  listen 80;
  server_name api.example.com;

  location / {
    root /var/www/vol/web/dist;        # 前端 dist
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    proxy_pass         http://127.0.0.1:9991/;
    proxy_http_version 1.1;
    proxy_set_header   Upgrade $http_upgrade;
    proxy_set_header   Connection "upgrade";
    proxy_set_header   Host $host;
    proxy_set_header   X-Real-IP $remote_addr;
    proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
  }

  location /message {
    proxy_pass         http://127.0.0.1:9991;
    proxy_http_version 1.1;
    proxy_set_header   Upgrade $http_upgrade;
    proxy_set_header   Connection "upgrade";
  }

  # 上传文件
  location /Upload/ {
    proxy_pass http://127.0.0.1:9991;
  }
}
```

### 8.3.4 Supervisor / systemd 守护后端

`/etc/supervisor/conf.d/volapi.conf`：

```ini
[program:volapi]
command=dotnet /var/www/vol/api/VOL.WebApi.dll
directory=/var/www/vol/api
autostart=true
autorestart=true
environment=ASPNETCORE_ENVIRONMENT=Production
stdout_logfile=/var/log/vol/api.out.log
stderr_logfile=/var/log/vol/api.err.log
user=www-data
```

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start volapi
```

## 8.4 Docker 部署

### 8.4.1 镜像构建

```bash
cd vol.api
docker build -t volapi:1.0 -f VOL.WebApi/Dockerfile .
```

`VOL.WebApi/Dockerfile`（关键阶段）：

```dockerfile
FROM mcr.microsoft.com/aspnet:8.0 AS base
WORKDIR /app
EXPOSE 8080
EXPOSE 8081

FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
ARG BUILD_CONFIGURATION=Release
WORKDIR /src
COPY ["VOL.WebApi/VOL.WebApi.csproj", "VOL.WebApi/"]
# ... 其它 csproj
RUN dotnet restore "./VOL.WebApi/VOL.WebApi.csproj"
COPY . .
WORKDIR "/src/VOL.WebApi"
RUN dotnet build "./VOL.WebApi.csproj" -c $BUILD_CONFIGURATION -o /app/build

FROM build AS publish
RUN dotnet publish "./VOL.WebApi.csproj" -c $BUILD_CONFIGURATION -o /app/publish /p:UseAppHost=false

FROM base AS final
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "VOL.WebApi.dll"]
```

### 8.4.2 启动容器

```bash
docker run -d \
  --name volapi \
  -p 9991:8080 \
  -v /etc/timezone:/etc/timezone:ro \
  -v /etc/localtime:/etc/localtime:ro \
  --restart=always \
  volapi:1.0
```

### 8.4.3 docker-compose 启动全套

`docker-compose.yml`（参考）：

```yaml
version: "3.8"
services:
  mysql:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: 123456
    ports: ["3306:3306"]
    volumes:
      - mysql_data:/var/lib/mysql
      - ../DB/mysql:/docker-entrypoint-initdb.d

  redis:
    image: redis:6
    ports: ["6379:6379"]

  volapi:
    build:
      context: .
      dockerfile: VOL.WebApi/Dockerfile
    depends_on: [mysql, redis]
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
      - Connection__DBType=MySql
      - Connection__DbConnectionString=Data Source=mysql;Database=vol_v3;User ID=root;Password=123456;AllowLoadLocalInfile=true;
      - Connection__RedisConnectionString=redis:6379
      - Connection__UseRedis=true
    ports: ["9991:8080"]
    volumes:
      - ./appsettings.json:/app/appsettings.json:ro

  volweb:
    image: nginx:alpine
    volumes:
      - ./vol.web/dist:/usr/share/nginx/html
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    ports: ["9990:80"]

volumes:
  mysql_data:
```

## 8.5 配置生产环境

### 8.5.1 关闭 Swagger

`Program.cs`：

```csharp
// 注释下面三行
// app.UseSwagger();
// app.UseSwaggerUI();
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
    app.UseSwagger();
    app.UseSwaggerUI();
}
```

### 8.5.2 修改密钥

`appsettings.json`：

```json
"Secret": {
  "JWT":   "<新值1>",
  "User":  "<新值2>",
  "DB":    "<新值3>",
  "Redis": "<新值4>"
},
"QuartzAccessKey": "<新值>"
```

### 8.5.3 跨域收敛

```json
"CorsUrls": "https://your-domain.com"
```

> 同时把 `Program.cs` 的 CORS 策略改为：
> ```csharp
> builder.WithOrigins("https://your-domain.com")
> ```

### 8.5.4 数据库连接字符串加密

> 框架提供 `Connection` 字段加密能力，使用 `SecurityEncDecrypt` + `Secret.DB` 作为密钥。

### 8.5.5 启用 HTTPS

- 使用 Nginx 反向代理终结 HTTPS
- 或在 ASP.NET Core 中配置 Kestrel 证书

```csharp
builder.WebHost.ConfigureKestrel(options =>
{
    options.Listen(IPAddress.Any, 9991, listenOptions =>
    {
        listenOptions.UseHttps("path/to/cert.pfx", "password");
    });
});
```

## 8.6 性能调优

| 项 | 建议 |
|----|------|
| 缓存 | `UseRedis=true`，配置 Redis 集群 |
| 响应压缩 | 启用 `AddResponseCompression` |
| 静态资源 | Nginx 托管前端，启用 gzip/brotli |
| 数据库 | 索引、读写分离、连接池 |
| 多实例 | ASP.NET Core 默认无状态，可水平扩展 |
| SignalR | 使用 Redis backplane（`AddSignalR().AddStackExchangeRedis()`） |
| 雪花 ID | 调整 `WorkerIdBitLength` / `SeqBitLength` |

## 8.7 监控与日志

- 日志：`VOL.Core/Services/Logger.cs` + `appsettings.json#Logging`
- 健康检查：`/swagger/` 或自定义 `/health`
- 异常：`ExceptionHandlerMiddleWare` 统一捕获
- 链路追踪：可接入 SkyWalking / OpenTelemetry（在 `Program.cs` 添加 `services.AddOpenTelemetry().WithTracing(...)`）

## 8.8 常见启动异常

参考 `vol.api/VOL.WebApi/dev_run启动异常说明.txt`，常见：

1. **数据库连接失败** — 检查 `Connection.DbConnectionString`
2. **Redis 不可用** — 临时改为 `UseRedis=false`
3. **500.30 ANCM In-Process Start Failure** — 查看 `Logs/` 下的 stdout
4. **雪花 ID 重复** — 调整 `WorkerId`
5. **Swagger 404** — 检查路由是否被 CORS/Middleware 截断

## 8.9 升级到新版本

- 框架升级：参考 `2.现有项目升级.doc` / `3.ef后台升级.net8.0.docx` / `4.sugar后台升级net8.0.docx`
- 业务升级：在新版本框架上重新生成业务 Service/Repository，然后 `git diff` 应用业务修改
- 数据库升级：执行 `2026.05月版本升级.zip` 中的 SQL 脚本
