```
vol-fullstack-dev
```

## 9.3 Skill 描述（Description）

```
该 Skill 用于在 Vue.NetCore（VOL）前后端分离框架上进行全栈开发，
包括：业务模块搭建、代码生成器使用、ServiceBase/RepositoryBase 扩展、
VolTable/VolForm/VolBox 组件开发、工作流与表单设计器、权限与多租户、
多数据库切换（MySQL/SQLServer/PG/Oracle/达梦）、EFCore 与 SqlSugar 双 ORM 选型、
Docker 部署、CI/CD 与生产环境配置。
```

## 9.5 标准开发流程

### Step 1：环境准备
1. .NET 8 / .NET 10 SDK
2. Node.js 20 + npm
3. 数据库（任选 5 种之一）
4. Redis（可选）
5. 拉取仓库并 `dotnet restore` + `npm install`

### Step 2：数据库初始化
1. 创建 `vol_v3` 库
2. 执行 `DB/<dbtype>/*.sql`
3. 改 `appsettings.json#Connection.DbConnectionString`

### Step 3：后端工程搭建
1. 在 `vol.api`（或 `vol.api.sqlsugar`）中新建业务类库 `VOL.<Module>`
2. 引用 `VOL.Core` + `VOL.Entity`
3. 定义实体（继承 `BaseEntity`）
4. 定义 `IRepository` / `Repository`（继承 `RepositoryBase<T>`）
5. 定义 `IService` / `Service`（继承 `ServiceBase<T, R>`）
6. 在 `VOL.WebApi.csproj` 中加入 `ProjectReference`
7. 如需走工作流，在 `Startup.cs` 中 `WorkFlowContainer.Instance.Use<T>(...)`

### Step 4：使用代码生成器生成前后端
1. 启动前端，访问 `/coder`
2. 选择表 → 配置 30+ 选项（字段、表单控件、查询、权限…）
3. 一键生成：实体 / Repository / Service / Controller / Vue 页面
4. 检查生成代码，按需扩展

### Step 5：前端开发
1. 路由：`router/viewGird.js` 动态加载
2. 页面：`views/<module>/<page>.vue`
3. 表格：使用 `<vol-table>` 或自定义列
4. 表单：使用 `<vol-form>` + `<vol-box>`
5. 权限：`v-permission` 指令
6. 国际化：`src/uitils/translator/`

### Step 6：业务扩展（核心）
1. **数据校验**：在 `Service` 构造函数中重写 `AddOnExecuting` / `UpdateOnExecuting`
2. **业务回写**：`UpdateOnExecuted` / `DelOnExecuted`
3. **自定义查询**：`QueryRelativeExpression` / `QuerySql` / `OrderByExpression`
4. **合计**：`SummaryExpress` / `SummaryExpressAsync`
5. **事务**：`repository.DbContextBeginTransaction(...)`
6. **原生 SQL**：`DapperContext` / `repository.ExecuteSqlCommand`

### Step 7：权限与多租户
1. 菜单权限：在 `Sys_Menu` 注册
2. 字段权限：`TableColumnContext` + `ApiAuthorizeFilter` 自动处理
3. 数据权限：`UserContext.DeptIds`（按部门隔离）
4. 多租户：`IsMultiTenancy = true` + `TenantId` 字段

### Step 8：审批流
1. 在 `Startup.cs` 中 `Use<T>("业务名", filterFields, formFields)`
2. 在前端调用 `service.SaveAudit(...)`
3. 在 `views/builder` 中配置流程图

### Step 9：表单设计器
1. 后端：`Form_DesignOptions` + `Form_CollectionObject` 表
2. 前端：`/formDraggable` 拖拽设计
3. 业务接入：`/formSubmit` 提交

### Step 10：测试 & 部署
1. `dotnet test`（如添加测试工程）
2. 前端 `npm run build`
3. Docker 构建：`docker build -t volapi:1.0 -f VOL.WebApi/Dockerfile .`
4. Nginx 反向代理 + Supervisor/systemd

## 9.6 核心代码模板

### 9.6.1 实体

```csharp
using VOL.Entity.SystemModels;
namespace VOL.Entity.DomainModels.Business
{
    public class MES_Order : BaseEntity
    {
        public int Id { get; set; }
        public string OrderNo { get; set; }
        public string MaterialCode { get; set; }
        public decimal Qty { get; set; }
        public DateTime CreateDate { get; set; }
    }
}
```

### 9.6.2 仓储

```csharp
using VOL.Core.BaseProvider;
using VOL.Core.EFDbContext;
using VOL.Entity.DomainModels.Business;
namespace VOL.Order.Repositories
{
    public class MES_OrderRepository : RepositoryBase<MES_Order>
    {
        public MES_OrderRepository(BaseDbContext dbContext) : base(dbContext) { }
    }
}
```

### 9.6.3 服务

```csharp
using VOL.Core.BaseProvider;
using VOL.Entity.DomainModels.Business;
namespace VOL.Order.Services
{
    public class MES_OrderService : ServiceBase<MES_Order, MES_OrderRepository>
    {
        public MES_OrderService(MES_OrderRepository repository) : base(repository) { }

        // 自定义查询
        public override WebResponseContent AddOnExecuting(MES_Order entity, object detail, bool add)
        {
            if (entity.Qty <= 0)
                return baseWebResponse.Error("数量必须大于0");
            return baseWebResponse.OK();
        }
    }
}
```

### 9.6.4 Controller（生成器产出）

```csharp
[Route("api/MES_Order")]
public class MES_OrderController : ApiBaseController<MES_Order>
{
    public MES_OrderController(IMES_OrderService service) : base(service) { }
    // Get / Add / Update / Del / PageData / Detail / Import / Export 全部由 ApiBaseController 提供
}
```

### 9.6.5 前端页面（生成器产出）

## 9.7 常见扩展场景对照表

| 业务需求 | 扩展位置 |
|----------|----------|
| 新增字段校验 | `AddOnExecuting` / `UpdateOnExecuting` |
| 列表自动加列 | `GetPageDataOnExecuted` |
| 列表加汇总 | `SummaryExpress` |
| 列表隐藏字段 | `TableColumnContext` + `Sys_Menu.TableAuth` |
| 列表加按钮 | `views/...` + 后端 `Sys_Menu.Auth` |
| 字典自动绑定 | `Sys_Dictionary` + `VolForm` 自动 |
| 主从表一对多 | 在 `MultipleTableEntity` 配置 |
| 列表分页/排序 | `PageDataOptions` + `OrderByExpression` |
| 上传图片 | `VolUpload` + 后端 `Upload` |
| 富文本 | `VolWangEditor` |
| 流程图 | `views/builder` + `components/workflow` |
| 自定义后端 API | 新建 Controller + Service |
| 定时任务 | 后端 `Quartz` + `[ApiTask]` |
| 站内消息 | 后端 `HomePageMessageHub` + 前端 SignalR 客户端 |
| 多语言 | `uitils/translator/` + `main.js` |
| 主题切换 | `main.js#global.theme` |

## 9.8 调试与排错清单

1. **接口 401**：检查 JWT 是否有效 / 菜单权限是否配置
2. **字段不显示**：检查 `TableColumnContext` / 字段权限
3. **保存失败**：检查 `AddOnExecuting` 返回值、数据库约束
4. **主从表保存丢明细**：检查 `MultipleTableEntity` 配置
5. **雪花 ID 重复**：调整 `SnowFlakeOptions#WorkerId`
6. **Dapper Guid 异常**：确认 `DBType` 与 `DapperParseGuidTypeHandler*` 匹配
7. **多租户过滤不生效**：确认实体有 `TenantId` 字段、`IsMultiTenancy=true`
8. **Swagger 404**：检查路由前缀 / 跨域
9. **SignalR 连不上**：检查 Nginx `Upgrade` 头 / CORS

## 9.10 适用本 Skill 的项目

- `vol.api` + `vol.web`（官方主推）
- `vol.api.sqlsugar` + `vol.web`（性能敏感）
- 任意基于 `VOL.Core` 改造的衍生项目

## 9.11 不适用场景

- 全新独立产品（无 VOL 依赖）
- 非前后端分离的纯后端 / 纯前端项目
- 非 .NET 平台（请使用对应的同类框架 Skill）
